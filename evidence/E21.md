- Physical snapshot tables remain in Chals' private `csv_dataset` BigQuery
  dataset.
- `csv_datasets`, the four warehouse/access/binding collections and the managed
  mart/preview collections are the control
  plane. They do not duplicate dataset rows.
- The workspace is the managed-data tenant. `user_id`, `created_by_user_id` and
  `updated_by_user_id` are actor/provenance fields, never an ownership shortcut.
  Legacy rows without `workspace_id` are migrated lazily only after their old
  owner and the active authenticated workspace have both been attested.
- Every eligible workspace receives one isolated dataset in Chals' existing
  `<cloud-project>` project. Its id is
  `chals_data_<workspace hash>` and it contains stable views only: raw
  publication views plus optional clean logical marts. No GCP
  project or billing account is created for the customer.
- Users receive `roles/bigquery.jobUser` on the existing Chals project and
  reader access only on their workspace dataset. They receive no access to
  private snapshots or another workspace dataset.
- Connected Sheets queries the selected raw or mart stable view with the workspace project as the
  billing project. A view is updated in place when the active Chals snapshot
  changes.
